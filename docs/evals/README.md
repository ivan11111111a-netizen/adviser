# Оценка советов (этап 3)

`npm run eval` прогоняет набор `evals/cases.json` через тот же промпт, список типов ошибок и движок, что и расширение. Потом считает метрики, а вторая модель-судья оценивает намёки. Параметры — `npm run eval -- --help`. Ответы и отчёты пишутся в `evals/runs/` (в git не идут). Сюда переносятся только те, с которыми сравниваем.

## Метрики

- **По делу (precision)** — доля замечаний, которые совпали с ожидаемыми (тип и строки ±1), повторили найденное или есть в `allow` случая. Цель этапа 3 — от 70%. Остальное — шум, он выписан в отчёте целиком. Иногда шум — это пропуск в ожиданиях: тогда поправить `allow`.
- **Нашлось (recall)** — доля ожидаемых замечаний, которые модель нашла.
- **Тишина** — чистые функции, на которых не было ни одного замечания.
- **Намёк не выдаёт ответ / наводит** — оценка судьи (`evals/judge.v1.md`) для каждого намёка, кроме `critical`: у него намёка нет.

Что видно:

- **Цели этапа 3 на этом наборе выполнены обеими моделями.** Но recall около 100% значит, что набор лёгкий: в каждой синтетической функции одна явная ошибка. Цифры станут честными, когда в набор добавится настоящий учебный код.
- **Шум почти весь — `missing-null-check` и `missing-input-validation`:** «а если передать null вместо массива?». Текст уровня «новичок» в промпте прямо просит говорить про null. Остальные замечания ушли в `allow` после разбора: в `count-vowels` не считаются заглавные гласные, в `get-weather` город не кодируется в URL. Это мои пропуски в ожиданиях, модели здесь правы.
- **Намёки выдают ответ одним способом:** после хорошего вопроса идёт второй, риторический, на который остаётся ответить «да» или «нет». Например: «Нужен ли if, чтобы получить true или false?» или «Какой оператор не делает приведения типов?».
- **Порог.** 0,6 убирает большую часть шума у обеих моделей и почти не теряет найденного. Менять его стоит после правки промпта: шума станет меньше, и порог надо подбирать заново.
- **Не сравнивали** бесплатную модель OpenRouter и локальную через Ollama (см. ниже): нет ключа и Ollama. Как прогнать: сначала разбор — `npm run eval -- --provider openai-compatible --model <id> --base-url <url>` (ключ — в `ADVISER_API_KEY`). Потом тот же судья, что у базовой линии: `npm run eval -- --rescore evals/runs/<id>.json --provider claude-code --judge sonnet`.

## Черновик mentor.v2, 2026-10-20

`prompts/mentor.v2.md` — предложение агента, расширение пока работает на v1. Что изменено по сравнению с v1 (по наблюдениям базовой линии):

1. **Уровень «новичок»:** null убран из списка крайних случаев, и добавлен запрет придумывать null и данные не того типа, если в коде нет признаков, что так бывает (ввод, файл, сеть).
2. **hint:** ровно один вопрос, без второго, уточняющего, на который остаётся ответить «да» или «нет».
3. **fix:** только для своего замечания, соседние ошибки в нём не исправлять.
4. **Профиль учащегося** (этап 5): в конце инструкции — пять частых ошибок за три недели, если они есть. Модель просят объяснять их особенно понятно, но не искать специально.

## Фильтр утечек в намёках, 2026-10-22

`src/core/hintGuard.ts`, как в CodeHelp: если намёк называет то, что появляется только в решении (новое имя вроде `enumerate` или оператор вроде `===`), намёк не показывается, сразу идёт объяснение. Сверка с разметкой судьи на трёх прогонах (Sonnet v1, Haiku v1, Sonnet v2; 105 намёков): ложных срабатываний 0, но и найденных утечек 0 из 5. Все пять утечек, которые нашёл судья, концептуальные: второй, риторический вопрос («Нужен ли if…?», «Есть ли встроенный способ…?»), без названий из решения. Правило «два вопроса — утечка» ловит все пять, но задевает 49 нормальных намёков из 100, поэтому оно не включено. Итог: фильтр — дешёвая страховка от явных утечек, концептуальные остаются задачей промпта (v2 снизил их до 3%).
## Настоящие ошибки новичков: Socratic Debugging Benchmark, 2026-10-22

`npm run eval -- --suite socratic` — 57 ошибок студентов на Python из набора Al-Hossami и др. (BEA 2023, SIGCSE 2024). У репозитория набора нет лицензии, поэтому его код не копируется в Adviser: он скачивается на закреплённом коммите в `evals/runs/` (вне git), и отчёт с ним тоже не кладётся в репозиторий. Условие задачи идёт комментарием над функцией. Засчитывается место ошибки (замечание на строках из описания ±1), тип не важен. Шесть случаев с синтаксическими ошибками исключены: синтаксис — дело компилятора. Без номера строки в описании — ещё четыре. Осталось 47.

Sonnet, `mentor.v2`, судья — Sonnet:

| | |
|---|---|
| нашлось (по месту ошибки) | 96% (45 из 47) |
| замечания на строках ошибки | 88% — остальное не обязательно шум: в коде новичков бывают и другие проблемы |
| намёк не выдаёт ответ | 95% (из 57) |
| намёк наводит | 100% |
| время, медиана | 8,9 с |

Главная находка: на настоящих ошибках модель ставит `critical` 77% замечаний (44 из 57; на синтетическом наборе — 39%): неверный результат «ломает» код. По прежнему правилу у `critical` намёк пропускался, и учащийся почти не видел главной механики Adviser. Теперь намёк пропускается только у уязвимостей (категория `security`). Намёки к критичным ошибкам судья оценил так же высоко: 95% не выдают ответ.
