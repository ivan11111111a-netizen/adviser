### js/average-price.js

- **match** reduce-without-initial, critical 0.95, строки 2–2
  - намёк: Чему равен sum на самой первой итерации reduce, когда второго аргумента нет, и что тогда получится в выражении sum + item.price?
  - объяснение: Без начального значения reduce берёт в качестве sum первый элемент массива, то есть целый объект, а не число. Выражение «объект + число» превращается в строку вроде "[object Object]5", и после деления получается NaN. Начальное значение 0 нужно, чтобы sum с самого начала был числом.
  - решение: Добавлено начальное значение 0 вторым аргументом reduce.
- **match** empty-collection, warning 0.85, строки 2–3
  - намёк: Что произойдёт при вызове averagePrice([]), когда в списке нет ни одного товара?
  - объяснение: Для пустого списка среднего значения не существует. Без начального значения reduce на пустом массиве вообще выбросит ошибку. А если начальное значение добавить, получится 0 / 0, то есть NaN. Правило такое: если функция принимает список, сразу подумай, что она вернёт для пустого. Сам реши, что вернуть: 0, null или ошибку.
  - решение: Перед вычислениями добавлена проверка на пустой список, для него возвращается 0.

- **allowed** loose-equality, suggestion 0.8, строки 3–3
  - намёк: Что вернёт сравнение `0 == ""` и можно ли быть уверенным, что `==` не сочтёт равными два разных по смыслу значения?

Для имён (строк) разница может быть незаметна, но привычку лучше выработать сразу.
