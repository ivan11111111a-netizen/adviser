# Adviser — ИИ-наставник для обучения программированию

**План разработки расширения для VS Code**

*Версия 2 · 5 октября 2026 · рабочий документ: правим по ходу обсуждения*

> **Что изменилось во второй версии.** Сменилась главная аудитория: не опытные разработчики в рабочих проектах, а те, кто учится программировать. Adviser теперь не ревьюер для продуктивности, а наставник — «сеньор, наблюдающий за джуном». Из этого следуют новые принципы (раздел 3), новая механика подачи советов (6.5), журнал ошибок и прогресса (6.6), другие метрики (15) и другие конкуренты (12). Версия 1 была написана под продуктивность опытного разработчика.

## Коротко

- **Что это.** Пока ты пишешь код, Adviser замечает изменённые функции и разбирает их как наставник: не просто «вот баг, вот фикс», а «смотри, что будет с пустым массивом — подумай, почему». Готовый код показывает последним, когда ты сам не дошёл.
- **Для кого.** Для тех, кто учится: студенты, самоучки, джуны в первый год работы. Для них прерывание в процессе — не помеха, а главное: ошибку надо показать, пока человек помнит, о чём думал.
- **Чем отличается.** Трёхступенчатая подача (намёк → объяснение → код), память о твоих повторяющихся ошибках, работа бесплатно (бесплатные тиры или локальная модель), настраиваемая частота. И путь роста: когда перестанешь быть джуном, тот же инструмент переключается в режим обычного ревьюера.
- **Цель.** Open source ради портфолио.
- **Объём.** Проверка идеи на себе (v0.1) — 25–36 часов, полный релиз — 78–114 часов. При ~10 ч в неделю это 3–4 недели и 2–3 месяца.
- **Что обсудить дальше** — раздел 16.

## 1. Позиционирование и аудитория

**Почему развернули проект.** В первой версии плана Adviser был тихим ревьюером для опытного разработчика. У этого сценария три слабых места:

1. Опытный человек в своём проекте уже знает, почему написал именно так — у него в голове контекст, которого у модели нет. Доля полезных советов падает там, где человек компетентен.
2. Прерывание в процессе работает против профи: он хочет дописать модуль целиком, а потом посмотреть. Не случайно все коммерческие ревьюеры срабатывают на коммите или в pull request — это момент, когда человек готов слушать.
3. Всё больше кода пишут агенты. «Советы кодеру во время написания» теряют адресата, если печатает агент, а человек ревьюит.

**Для учащегося те же свойства работают в плюс:**

| Свойство | Для опытного | Для учащегося |
|---|---|---|
| Прерывание в процессе | мешает, ломает поток | **нужно** — урок усваивается, пока помнишь свои мысли |
| Объяснение «почему» | лишний текст, он и так знает | **главная ценность** |
| Советы про основы | придирки | **то, чего не хватает** |
| Готовый код исправления | экономит время | **вредит** — применяет не думая |
| Память о повторах | не нужна | **ядро продукта** — так и работает наставник |

**Портрет пользователя.** Учится программировать 3–18 месяцев. Пишет учебные проекты или первые рабочие задачи. Код формально работает, но содержит типовые ошибки, о которых некому сказать: нет обработки краёв, мутация аргументов, проглоченные исключения, копипаста вместо функции. Ревьюера рядом нет. Платить не готов или почти не готов.

**Границы: чего Adviser сознательно не делает.** Не пишет код за пользователя, не решает домашние задания, не превращается в чат «сделай мне». Это и этическая позиция, и защита от того, чтобы продукт стал ещё одним способом не учиться. В README это написано прямо.

## 2. Принятые решения

| Вопрос | Решение | Что из этого следует |
|---|---|---|
| Аудитория | учащиеся программированию | Механика наставника в ядре, а не в опциях; объяснения важнее скорости |
| Цель | open source ради портфолио | Бесплатно, код на GitHub, лицензия MIT. Упор на README, тесты, демо |
| Модели | бесплатный тир → локально → свой ключ | Три варианта в мастере первого запуска, бесплатный первым (6.9) |
| Языки для тестов | JavaScript / TypeScript и Python | Пресеты и eval-набор под них, ядро универсальное |
| Разработка | с ИИ-агентом | Этапы с критериями готовности, AGENTS.md в репозитории (раздел 11) |
| Путь роста | режим «ревьюер» как переключатель | Пользователь не меняет инструмент, когда вырос |
| Язык советов | по языку интерфейса VS Code (русский интерфейс — советы по-русски, иначе по-английски) и настройка `adviser.language` | Тексты промпта для каждого языка; у кого английский интерфейс, тот меняет настройку |
| Типы ошибок | `patterns/patterns.json`: черновик пишет агент, автор вычитывает | После вычитки id не меняются, на них держится журнал повторов (6.6) |

## 3. Ключевые принципы

1. **Учим, а не исправляем.** Цель каждого совета — чтобы в следующий раз человек написал правильно сам. Отсюда вся механика подачи (6.5).
2. **Намёк раньше ответа.** Готовый код — последняя ступень, по явному запросу. Сопротивление и есть урок.
3. **Не дублировать линтеры.** Что ловят ESLint, TypeScript, Ruff и Pylance — не наша работа, их замечания идут в контекст. Наше — логика, крайние случаи, уместность решения, привычки.
4. **Единица проверки — изменённая функция** (метод, класс) плюс diff. Не файл целиком и не отдельная строка.
5. **Молчание — нормальный ответ.** Модели разрешено сказать «замечаний нет». Не больше 3 советов на функцию, есть порог уверенности. Учащегося завалить легко, и тогда он всё выключит.
6. **Подстройка под уровень.** Новичку не говорим про архитектуру, пока у него течёт обработка ошибок. Уровень задаётся и уточняется по ходу (6.7).
7. **Память о повторах.** Наставник отличается от линтера тем, что помнит: «ты так делаешь третий раз за неделю».
8. **Структуру кода берём у VS Code.** Языковые серверы уже знают, где функции и какие есть ошибки. Свои парсеры не нужны.
9. **Бесплатный вход обязателен.** Если для старта нужна карта, учащийся уйдёт. Бесплатный путь — первый в мастере настройки.
10. **Приватность по умолчанию.** Согласие при первом запуске, маскировка секретов, игнор-списки, полностью локальный режим.
11. **Советы, а не действия.** Код меняется только по явному клику и с превью.

## 4. Как это работает

```text
 Редактор VS Code
   │  правки · сохранения · курсор
   ▼
 ① Трекер изменений ──────── какие функции «грязные»
   ▼
 ② Планировщик ───────────── пора? (триггеры, лимиты, cooldown)
   ▼
 ③ Сборщик контекста ─────── функция + diff + скелет файла + правила
   │                          + профиль учащегося + его частые ошибки
   ▼
 ④ Фильтр приватности ────── маскировка секретов, игнор-списки
   ▼
 ⑤ Кэш ── нет в кэше ──────► ⑥ Движок: промпт → модель → JSON
   ▼
 ⑦ Наставник ─────────────── ступень 1: намёк
   │                          ступень 2: объяснение «почему»
   │                          ступень 3: код (по запросу)
   ▼
 ⑧ Журнал ошибок ─────────── тег паттерна, счётчик повторов, отчёт
   ▼
 ⑨ Обратная связь ────────── «понял» / «не согласен» / «не показывать»

 Сквозные модули: ⑩ профиль и правила · ⑪ бюджет и доступ к моделям
```

## 5. Чем Adviser отличается от наставника-человека

Полезно держать в голове, чего инструмент принципиально не умеет — чтобы не обещать лишнего ни в README, ни себе.

| Умеет наставник-человек | Умеет ли Adviser |
|---|---|
| Видеть, что человек застрял, по лицу и паузам | Нет. Только по коду и паузам в наборе |
| Объяснить, почему так принято в этой команде | Частично — из файлов правил проекта |
| Дать задачу на отработку слабого места | Нет. Может только показать статистику повторов (6.6) |
| Сказать «забудь, сейчас это не важно» | Частично — через уровень и приоритеты категорий |
| Разобрать архитектуру целиком | Нет. Работает в границах функции и её окружения |
| Быть рядом в 2 часа ночи перед дедлайном | Да. В этом и смысл |

Вывод для продукта: Adviser закрывает узкую, но частую потребность — быстрая обратная связь по только что написанному коду. Не заменяет курс, ментора и код-ревью в команде, и README говорит это прямо.

## 6. Модули подробно

### 6.1. Трекер изменений

- Слушает правки в открытых файлах и копит изменённые строки.
- Сопоставляет их с функциями через встроенную команду `vscode.executeDocumentSymbolProvider` — функция помечается «грязной».
- Для каждой функции хранит: хэш содержимого на момент последней проверки, время последней правки, объём изменений.
- Пропускает: правки только в пробелах и комментариях, сгенерированные и минифицированные файлы, игнор-лист, очень большие файлы, служебные документы.

Как найти границы функции:

| Способ | Плюсы | Минусы |
|---|---|---|
| Символы языкового сервера | Любой язык, для которого стоит расширение | Зависит от языкового расширения; на больших файлах бывает медленно |
| tree-sitter (WASM) | Точно, быстро, без других расширений | Грамматика под каждый язык, тяжелее пакет |
| Отступы и скобки | Просто | Ненадёжно |

**Решение:** символы языкового сервера; если их нет — изменённые строки ± 10 строк. tree-sitter — только если языковые серверы подведут.

### 6.2. Планировщик: когда срабатывать

| Триггер | Когда | По умолчанию |
|---|---|---|
| Уход из функции | курсор покинул изменённую функцию | вкл |
| Сохранение | файл сохранён | вкл |
| Пауза | нет правок N секунд | вкл, 30 с (учащийся часто «застрял», а не думает) |
| Вручную | команда или хоткей «Разобрать эту функцию» | всегда доступно |

Автоматическая проверка запускается, только если выполнено всё сразу:

- в функции нет синтаксических ошибок (Error-диагностик в её строках) — иначе человек ещё печатает;
- изменение значимое: хэш другой и изменено не меньше N строк;
- с прошлой проверки этой функции прошло не меньше cooldown;
- не превышены лимиты: проверок в час и в день.

Дополнительно: несколько готовых функций уходят одним запросом; если функция изменилась, пока шла проверка, запрос отменяется.

Режимы (переключаются в статус-баре):

| Режим | Триггеры | Лимит | Для чего |
|---|---|---|---|
| Ручной | только команда | — | полный контроль |
| **Наставник** (по умолчанию) | уход из функции + сохранение + пауза 30 с | ≤ 20 в час | учёба |
| Ревьюер | уход из функции + сохранение | ≤ 6 в час | когда вырос: кратко, без объяснений, сразу код |
| Свой | любая комбинация | задаёшь сам | — |

Плюс «Не беспокоить» на 30 или 60 минут одним кликом — для экзамена, демо и записи экрана.

### 6.3. Сборщик контекста

Слоями, по приоритету, в пределах бюджета токенов (например, до 6 000 на запрос):

1. Сама функция с пронумерованными строками + diff с прошлой проверенной версией.
2. «Скелет» файла: импорты, сигнатуры соседних функций и класса, без тел.
3. Сигнатуры того, что функция вызывает (`vscode.executeDefinitionProvider`).
4. Замечания линтера и компилятора в этих строках — чтобы их не повторять.
5. **Профиль учащегося:** уровень, язык, 5 самых частых его ошибок (6.6), темы, которые он просил не трогать.
6. Версии зависимостей из `package.json`, `pyproject.toml`, `requirements.txt` — чтобы не советовать несуществующие API.
7. Правила стиля: `.adviser/rules.md` и, если включено, AGENTS.md, CLAUDE.md, `.cursorrules`, `.github/copilot-instructions.md`.

- Порядок в промпте: всё стабильное (инструкция, правила, профиль) в начале, код в конце — так срабатывает кэширование промпта у провайдера и запросы дешевеют.
- Функция длиннее ~150 строк → отправляем изменённые части с сигнатурой.

### 6.4. Движок проверки

**Провайдеры** подключаются через общий интерфейс:

| Провайдер | Что покрывает | Когда |
|---|---|---|
| OpenAI-совместимый | **OpenRouter (включая бесплатные модели)**, OpenAI, DeepSeek, Groq, LM Studio и **Ollama** (через `/v1`) | MVP |
| Mock | заготовленные ответы для тестов, без трат | MVP |
| Anthropic | Claude + управляемое кэширование промпта | v0.5 |
| Модели Copilot | VS Code Language Model API | после 1.0 |

**Реализация:** Vercel AI SDK (`ai`) — один вызов для всех провайдеров и ответ сразу по zod-схеме.

**Ответ модели — строго JSON по схеме.** Проверяем через zod; невалидный ответ — один повтор, потом тихая ошибка. Ключевое отличие от версии 1 — три уровня текста в каждом замечании:

```json
{
  "summary": "Работает, но упадёт на пустом списке",
  "issues": [
    {
      "patternId": "reduce-without-initial",
      "category": "edge-case",
      "severity": "warning",
      "confidence": 0.9,
      "startLine": 4,
      "endLine": 4,
      "hint": "Что вернёт эта строка, если items окажется пустым?",
      "explanation": "reduce без начального значения берёт первый элемент массива как стартовый. Если массив пуст, брать нечего — JavaScript бросает TypeError. Начальное значение решает это и заодно задаёт тип результата.",
      "fix": {
        "description": "Передать 0 вторым аргументом reduce",
        "code": "const total = items.reduce((sum, x) => sum + x, 0);"
      },
      "readMore": "https://developer.mozilla.org/ru/docs/Web/JavaScript/Reference/Global_Objects/Array/reduce"
    }
  ]
}
```

- `hint` — ступень 1, вопрос без ответа. `explanation` — ступень 2, «почему». `fix` — ступень 3.
- `patternId` — устойчивый идентификатор типа ошибки для журнала повторов (6.6). Модель выбирает из списка известных паттернов, который лежит в репозитории; если ничего не подошло — `other` плюс своя формулировка.
- Категории: `bug`, `edge-case`, `security`, `performance`, `readability`, `style`, `project-fit`.
- Серьёзность: `critical`, `warning`, `suggestion`. Номера строк — относительно функции, расширение пересчитывает их в строки файла.

**Промпт** лежит в `prompts/` с версией в имени (она же в ключе кэша). Главное в нём: роль наставника, который хочет, чтобы человек понял, а не чтобы код стал правильным; требование задать вопрос прежде, чем дать ответ; запрет повторять линтер; уровень учащегося; «если всё хорошо — пустой список».

**Ошибки** (нет сети, лимит провайдера, таймаут) — без всплывающих окон: значок в статус-баре и повтор с паузой.

### 6.5. Механика наставника — ядро продукта

Трёхступенчатое раскрытие. Модель отдаёт все три уровня сразу (один запрос), а расширение показывает их по мере того, как человек нажимает.

| Ступень | Что видно | Как открыть |
|---|---|---|
| 1. Намёк | подчёркивание + вопрос в hover: «Что вернёт эта строка, если `items` пуст?» | автоматически |
| 2. Объяснение | «почему» на 2–4 предложения + ссылка на документацию | кнопка «Объяснить» |
| 3. Код | готовое исправление с превью | кнопка «Показать решение» |

**Почему именно так:**

- Если сразу показать код, учащийся нажмёт «применить» и ничего не поймёт. Это главная причина, по которой обычные ИИ-ревьюеры для учёбы не годятся.
- Если не показать код вовсе, человек застрянет и выключит расширение. Третья ступень нужна, просто она не первая.
- Переход на следующую ступень — это сигнал: сколько раз человек дошёл сам, не открывая решение, и есть главная метрика (раздел 15).

**Детали, которые нужно продумать при реализации:**

- Сколько ждать перед автоматическим раскрытием второй ступени? Вариант: не раскрывать никогда автоматически, но если человек правит ту же строку больше 2 минут — предложить.
- ~~Для `critical` ступени смешиваются: если код сломан или есть уязвимость, намёк неуместен, показываем объяснение сразу.~~ Изменено 2026-10-22: намёк пропускается только у уязвимостей (категория `security`) и когда фильтр утечек убрал его как выдающий ответ. На настоящих ошибках новичков модель ставит `critical` 77% замечаний: неверный результат «ломает» код. С прежним правилом учащийся почти не видел намёков (`docs/evals/README.md`).
- В режиме «Ревьюер» ступени отключены: сразу объяснение одной строкой и код.
- На второй ступени, рядом с объяснением, — пример, на котором ошибка видна: вызов и что получится (с `mentor.v3`).
- «Проверь меня» (этап 9): пока виден только намёк, учащийся объясняет ошибку своими словами, модель говорит, верно ли. Верно — открывается объяснение, случай в журнале отмечается «объяснил сам».
- Пауза перед третьей ступенью (`adviser.solutionDelay`, вопрос 2 раздела 16): `auto` включает минуту ожидания, если за две недели решение открывали в 70% случаев и чаще.

### 6.6. Журнал ошибок и прогресс

То, чего нет у линтеров и ревьюеров: память о привычках конкретного человека.

- Каждое замечание пишется в локальный журнал: `patternId`, файл, время, язык, дошёл ли человек сам (до какой ступени открыл), исправил ли.
- Повтор того же `patternId` меняет подачу: в третий раз Adviser добавляет «ты так уже делал 2 раза на этой неделе» и ссылку на прошлый случай.
- **Недельный отчёт** в боковой панели: топ-5 твоих паттернов, что ушло по сравнению с прошлой неделей, доля «дошёл сам».
- Паттерн, который не повторялся 3 недели, считается освоенным и уходит из профиля — иначе список растёт бесконечно.
- Всё хранится локально (JSON в `globalStorageUri`), никуда не отправляется, кроме пяти верхних паттернов в промпт.

Это и самая ценная часть для портфолио: она превращает расширение из обёртки вокруг LLM в продукт со своей логикой.

### 6.7. Профиль учащегося, стиль и правила

Три слоя настроек:

1. **Настройки VS Code (пользователь):** провайдер, модель, адрес сервера, режим, лимиты, язык советов, уровень, навязчивость.
2. **`.adviser/config.json` (проект, в git):** триггеры, категории, минимальная серьёзность, игнор, пресеты.
3. **`.adviser/rules.md` (проект, в git):** правила стиля обычным текстом.

Проектные настройки перекрывают пользовательские. **Исключение — провайдер, адрес сервера и модель: только из настроек пользователя.** Иначе чужой репозиторий мог бы перенаправить код и ключ на свой сервер.

**Уровень** — главный параметр профиля:

| Уровень | О чём говорим | О чём молчим |
|---|---|---|
| Новичок | синтаксис, крайние случаи, именование, обработка ошибок | архитектура, производительность, паттерны |
| Средний | + структура функций, дубли, типы | крупная архитектура |
| Продвинутый | всё | — |

Уровень задаётся при первом запуске (один вопрос) и уточняется по ходу: если человек стабильно доходит до решения сам, Adviser предлагает поднять уровень.

Пример `.adviser/config.json`:

```json
{
  "mode": "mentor",
  "level": "beginner",
  "triggers": { "onSave": true, "onLeaveFunction": true, "idleSeconds": 30 },
  "limits": { "perHour": 20, "perDay": 60, "cooldownMinutes": 5, "maxIssuesPerBlock": 3 },
  "minSeverity": "suggestion",
  "categories": { "style": true, "performance": false, "security": true, "project-fit": false },
  "language": "ru",
  "readAgentFiles": true,
  "ignore": ["dist/**", "**/*.min.js", "node_modules/**"]
}
```

Пресеты на старте: `ts-strict`, `js-modern`, `python-pep8` — короткие .md-файлы внутри расширения.

### 6.8. Показ советов

| Элемент | Что показывает | Когда видно |
|---|---|---|
| Статус-бар | режим, «разбираю…», число советов, расход; по клику — меню | всегда |
| Подчёркивание (диагностики) | волнистая линия + вкладка «Проблемы», источник «Adviser» | сразу |
| Hover | ступень 1 (вопрос) и кнопки «Объяснить» / «Показать решение» | при наведении |
| Лампочка (Quick Fix) | применить решение с превью, «понял», «не показывать этот паттерн» | по клику |
| CodeLens над функцией | «Adviser: 2 замечания» | если включено |
| Боковая панель | журнал, недельный отчёт, прогресс, расходы | по открытию |
| Уведомления | только критичное | по умолчанию выкл |

- Серьёзность → уровень VS Code: `critical` → Warning, `warning` → Information, `suggestion` → Hint. Уровень Error не используем никогда, чтобы не путать с ошибками компилятора.
- Советы — снимок на момент проверки. Правишь функцию — они сбрасываются или помечаются устаревшими.

### 6.9. Доступ к моделям и бюджет

Для учащегося это решающий раздел: если на входе нужна банковская карта, он не начнёт.

**Три пути в мастере первого запуска, в этом порядке:**

1. **Бесплатно через OpenRouter.** Бесплатные модели (суффикс `:free`): без оплаты — 50 запросов в сутки и 20 в минуту; после единоразовой покупки кредитов на $10 суточный лимит становится 1000 и остаётся таким, даже если баланс потом опустится. 50 в сутки для учёбы хватает: это примерно полтора часа активной работы в режиме «Наставник». Бесплатные модели могут отдавать 429 в часы пик — расширение переживает это молча, с повтором.
2. **Локально через Ollama.** Бесплатно и ничего не уходит в сеть. Нужно железо: модели уровня `qwen2.5-coder:7b` работают на 8 ГБ видеопамяти, `qwen2.5-coder:14b` и `gpt-oss:20b` — на 16 ГБ. На слабой машине этот путь закрыт, и мастер это честно скажет.
3. **Свой ключ** любого провайдера — для тех, кто готов платить за качество.

**Важно сказать в окне согласия:** у бесплатных тиров провайдер обычно оставляет за собой право использовать запросы для улучшения своих моделей. Для учебного кода это обычно приемлемо, для рабочего — нет. Поэтому в мастере рядом с бесплатным путём стоит пометка «для учебных проектов».

**Учёт расходов** (для тех, кто на своём ключе): токены из ответа API × редактируемая таблица цен → расход за день и месяц; лимиты в $; при исчерпании — пауза или переход на локальную модель. Грубая оценка размера запроса перед отправкой.

Ориентир стоимости для платного пути (4 000 входных токенов, из них 1 500 кэшируются, + 600 выходных; 30 проверок в день, 20 дней):

| Модель | За проверку | За день | За месяц |
|---|---|---|---|
| Бесплатные модели OpenRouter | $0 | $0 | $0 (в пределах 50/сутки) |
| Ollama локально | $0 | $0 | $0 (электричество) |
| Claude Haiku 4.5 ($1 / $5 за млн токенов) | ≈ $0,006 | ≈ $0,17 | ≈ $3,4 |
| Claude Sonnet 5 ($2 / $10, новый токенизатор даёт ≈ +30% токенов) | ≈ $0,015 | ≈ $0,44 | ≈ $8,8 |

Лимиты бесплатных тиров меняются — проверить заново на этапе 0 и перед релизом.

### 6.10. Приватность и безопасность

- **Согласие при первом запуске:** какой провайдер получит код, что именно уходит, и предупреждение про бесплатные тиры (6.9).
- **Ключи — только в SecretStorage**, никогда в `settings.json`.
- **Не отправляем** `.env*` и файлы из `.adviserignore` (по желанию — и из `.gitignore`).
- **Маскировка секретов** перед отправкой: регулярные выражения и энтропия, например на базе secretlint.
- **Workspace Trust:** в недоверенных папках расширение выключено — конфиг или комментарии в чужом репозитории могут содержать промпт-инъекцию.
- Код и правила из репозитория идут в промпт только как данные; советы никогда не выполняются автоматически.
- **Журнал ошибок не покидает машину** (кроме пяти верхних паттернов в промпте).
- **Телеметрии нет.** Вся статистика локальная.

### 6.11. Обратная связь

- На каждом совете: «понял», «не согласен», «не показывать этот паттерн».
- «Не согласен» несколько раз на одном паттерне → предложить отключить его.
- Отключённые паттерны и категории пишутся в настройки.
- Переходы по ступеням и «понял» идут в журнал (6.6) — это и есть измерение пользы.

## 8. Технический стек

- **Язык:** TypeScript; расширение работает в Node.js внутри VS Code.
- **Скелет:** генератор `yo code` (TypeScript + esbuild).
- **Сборка:** esbuild — один файл, быстрая активация.
- **Модели:** Vercel AI SDK (`ai`) + провайдеры: OpenAI-совместимый, Anthropic, Ollama (`ai-sdk-ollama` или `ollama-ai-provider-v2`).
- **Схемы и валидация:** zod.
- **Секреты:** secretlint или свои регулярные выражения.
- **Хранилище:** SecretStorage для ключей, `globalState` и JSON-файлы в `globalStorageUri` для журнала. **Без нативных модулей** (sqlite и подобных) — иначе придётся собирать расширение под каждую ОС.
- **Панель (webview):** `@vscode-elements/elements` — официальный Webview UI Toolkit закрыт с 1 января 2025.
- **Тесты:** Vitest для ядра, `@vscode/test-cli` + `@vscode/test-electron` для интеграционных, mock-провайдер.
- **Оценка качества:** promptfoo или свой скрипт.
- **Качество кода:** ESLint + Prettier.
- **CI/CD:** GitHub Actions — линт, тесты, сборка `.vsix`; отдельный workflow для релиза.
- **Публикация:** `@vscode/vsce` (Marketplace) и `ovsx` (Open VSX).

**Главное архитектурное правило: ядро (`src/core`) не импортирует `vscode`.** Вся работа с редактором — в тонких адаптерах. Тогда планировщик, контекст, журнал и бюджет покрываются быстрыми юнит-тестами, а агенту сложнее что-то сломать.

## 11. Работа с ИИ-агентом

- **AGENTS.md в корне** — один файл правил для любых агентов. Claude Code читает его сам начиная с версии 2.1.277, если в проекте нет CLAUDE.md; если CLAUDE.md есть — достаточно строки `@AGENTS.md` в нём. Держать до ~200 строк.
- **Что в AGENTS.md:** команды сборки и тестов, структура папок, архитектурные правила (ядро без `vscode`, внешние данные через zod, ключи только в SecretStorage), «к каждой функции ядра — тест», «новые зависимости только по согласованию».
- **Этап → 3–6 маленьких задач.** В каждой: цель, файлы, критерий готовности, как проверить.
- Агент пишет тесты вместе с кодом; ты запускаешь расширение по F5 и смотришь руками.
- Коммит после каждой рабочей задачи, отдельная ветка на этап.
- Mock-провайдер — агент гоняет тесты, не тратя токены.
- **Промпты и тексты объяснений пиши или вычитывай сам.** Это главное качество продукта, и именно здесь агент даёт самый незаметный брак: формально правильные, но пустые объяснения.

Шаблон задачи для агента:

```text
Задача 2.3 — вторая ступень раскрытия
Цель: кнопка «Объяснить» в hover показывает explanation, не раскрывая fix.

Готово, когда: тесты на переходы ступеней проходят;
```

## 12. Конкуренты

Две разные группы, и важна вторая.

**Группа 1 — ревьюеры для продуктивности.** Большие, зрелые, но решают другую задачу: быстрее влить код, а не научить человека.

| Продукт | Когда проверяет | Модели | Установки |
|---|---|---|---|
| GitHub Copilot (code review) | вручную: выделение или незакоммиченные изменения | только Copilot | десятки млн (весь Copilot) |
| CodeRabbit (IDE) | после коммита или вручную | их облако | ≈ 189 тыс. |
| Qodo | перед коммитом | их облако | ≈ 905 тыс. |
| LGTM (open source) | git-изменения | модели Copilot | ≈ 3,7 тыс. |

Ни один не объясняет «почему» специально для учащегося, не прячет решение и не помнит твои повторы. Они и не должны: их пользователь хочет быстрее закрыть PR.

**Группа 2 — прямые конкуренты в обучении.** Они существуют, и это важная поправка: идея приходит в голову не только нам. Но ни один не стал заметным.

| Продукт | Что делает | Установки в Marketplace |
|---|---|---|
| **Protege** | «ИИ-наставник в редакторе»: live review как печатаешь, локальная Qwen 7B в комплекте, подстройка под уровень, механика «угадай, потом посмотри» | ≈ 20, рейтинг 2★ |
| **Bug2Brain** | превращает твои ошибки в учебную программу: упражнения, флеш-карточки с интервальным повторением, дашборд прогресса | ≈ 6, без отзывов |
| Python Code Mentor | объяснения и квизы по Python | — |
| DevSENSEI, Dev Tutor, Accelode, Vibe Check | разные варианты «ИИ учит понимать код», часто через квизы | по сотням загрузок в Open VSX |

**Что из этого следует — честно:**

1. **Идея не уникальна.** Protege реализовал почти то же, что мы задумали, включая прятанье ответа и локальную модель.
2. **Но лидера нет, и планка низкая.** 20 установок и 2 звезды — это не «рынок занят», это «сделать хорошо трудно». Падают на качестве советов и на шуме, а не на идее. Отсюда и решение поставить eval-набор (этап 3) раньше автоматики.
3. **Возможно, спрос со стороны пользователей невелик.** Учащийся скорее откроет ChatGPT и спросит. Это настоящий риск, а не придирка (раздел 14).
4. **Чем отстраиваемся:** любая модель вместо одной вшитой (включая бесплатные тиры и свой ключ); журнал повторов на уровне конкретных паттернов, а не общий дашборд; работа на твоём собственном коде, без отвлечения на квизы и упражнения; настраиваемая частота вмешательства; переключение в режим обычного ревьюера, когда вырос.

## 13. Публикация и портфолио

**Где публикуем:**

- **VS Code Marketplace** — через `vsce`. ⚠️ **1 декабря 2026 Azure DevOps отключает глобальные PAT**, на которых раньше держалась публикация. Токены не заводим вообще: у `vsce` есть trusted publishing — `vsce publish --oidc` прямо из GitHub Actions. Настройка: политика доверенной публикации для репозитория и workflow на стороне Marketplace, в workflow — `permissions: id-token: write` и `contents: read`, Node 22+. Секретов в репозитории не хранится совсем.
- **Open VSX** — через `ovsx`: вход через GitHub, аккаунт Eclipse, соглашение издателя, создание namespace, токен в секретах CI. Отсюда ставят расширения Cursor, Windsurf и VSCodium.
- **GitHub Releases** — `.vsix` для ручной установки (так раздаём v0.5).
- **Версии:** pre-release — с нечётной минорной цифрой (0.3.x, 0.5.x), релиз — с чётной (1.0.x), как советует документация VS Code.

**Требования Marketplace:** иконка PNG от 128×128 (SVG нельзя); картинки в README только по https; уникальны и имя, и отображаемое имя; не больше 30 ключевых слов.

**Для портфолио:**

- README: гифка с тремя ступенями на первом экране — это то, что сразу объясняет продукт. Дальше: «зачем», установка (бесплатный путь первым), приватность, честное «чего не делает».
- MIT, CONTRIBUTING.md, шаблоны issues, бейджи (CI, версия, установки).
- Статья «Как я сделал ИИ-наставника для VS Code» — с разбором eval-набора и цифрами качества советов. Это самая сильная часть истории: показывает, что ты измеряешь, а не на глаз.
- **Где искать первых пользователей:** своя группа и однокурсники, чаты курсов по программированию, r/learnprogramming, r/vscode. Обучающая аудитория достижимее, чем профессиональная: ей не нужно встраивать инструмент в рабочий процесс команды.
- Цифры для резюме: установки, звёзды, результаты eval, доля «дошёл сам» по журналу.

## 14. Риски

| Риск | Что делаем |
|---|---|
| **Спроса нет: учащиеся просто спрашивают ChatGPT** | главный риск. Проверяем на себе после v0.1, потом на 5–10 однокурсниках, прежде чем вкладывать 50+ часов. Наше преимущество перед чатом — само замечает и помнит повторы, не надо ничего копировать |
| Плохие советы, придирки, шум | eval-набор до автоматики (этап 3), «молчание — норма», ≤ 3 совета, порог уверенности, уровень учащегося, «не показывать паттерн» |
| Намёк превращается в бессмысленную загадку | в eval отдельная метрика на качество намёков; `critical` показываем сразу |
| Учащийся сразу жмёт «Показать решение» и не думает | переход по ступеням логируется; если это постоянно, Adviser сам предлагает включить паузу перед третьей ступенью |
| Нет денег и нет железа под модель | бесплатный тир OpenRouter первым в мастере; локальный путь честно отключается на слабой машине |
| Бесплатные тиры: данные уходят на обучение моделей | прямая пометка в мастере и в PRIVACY.md, «для учебных проектов» |
| Лимиты бесплатных тиров изменятся | проверять на этапе 0 и перед релизом; при 429 — молчаливый повтор, а не ошибка в лицо |
| Утечка кода или секретов | согласие, маскировка, игнор-списки, локальный режим, журнал не покидает машину |
| Промпт-инъекция из чужого репозитория | Workspace Trust, репозиторий только как данные, никаких автодействий, адрес сервера только из настроек пользователя |
| Прямые конкуренты (Protege и другие) | их слабое место — качество и шум; разбираем их на этапе 0 и не повторяем |
| Remote-разработка (WSL, SSH) | расширение работает на удалённой стороне, `localhost` для Ollama там другой → явная настройка адреса + подсказка в README |
| Проект затянется | останавливаемся на v0.1 и проверяем; резать объём, а не сроки |

## 15. Метрики успеха

Главное отличие от версии 1: меряем не «применили ли совет», а «понял ли человек».

- **Доля «дошёл сам»** — замечания, где человек исправил код, не открывая третью ступень. Это основная метрика продукта. Ориентир: от 30%.
- **Освоенные паттерны** — сколько типов ошибок перестали повторяться за месяц. Прямое доказательство, что инструмент учит.
- **«Объяснил сам»** — сколько ошибок человек объяснил своими словами через «Проверь меня» (этап 9). Это ещё ближе к «понял», чем «дошёл сам».
- Доля «не согласен» и «не показывать» — чем ниже, тем меньше шума.
- Тишина на чистом коде: доля проверок без замечаний на корректном коде (по eval).
- Задержка от триггера до намёка — ориентир до 10 с в облаке.
- После релиза: установки, активные через 7 и 30 дней, звёзды, отзывы.

## 16. Открытые вопросы — обсудим

1. **Имя.** «Adviser» под наставничество звучит слабовато, а в Open VSX уже есть несколько «… Adviser / … Advisor». «Mentor» занят (`faubulous.mentor`), «Code Mentor» и «AI Mentor» — нет. Ищем своё?
2. ~~**Паузу перед третьей ступенью**~~ — решено 2026-10-22 (автор поручил агенту): по журналу, `adviser.solutionDelay: auto`. Если за две недели решение открывали в 70% случаев и чаще (из хотя бы 10), «Показать решение» появляется через минуту. Ещё есть `always` и `off`. Критичные ошибки и «Ревьюер» — без паузы.
3. ~~**Язык советов по умолчанию**~~ — решено 2026-10-13: по языку интерфейса VS Code, плюс настройка (раздел 2).
4. ~~**`patterns.json`**~~ — решено 2026-10-13: черновик пишет агент, автор вычитывает (раздел 2).
5. **Проверка спроса до кода:** может, сначала спросить 10 однокурсников, пользовались бы они таким, и только потом начинать этап 1? Код уже есть, поэтому теперь — пилот на однокурсниках: `docs/PILOT.md`.
6. ~~**Разбор кода ИИ-агента**~~ — сделан в этапе 9 (2026-10-22, автор поручил все доработки): команда «Понимаю ли я изменения» и предложение после большой правки файла извне. Сильная ли это фишка, покажет пилот.
7. **Ключ какого провайдера** берём для платного пути в тестах? Второй провайдер после OpenAI-совместимого — GitHub Copilot через VS Code (этап 9): без ключа, студентам бывает бесплатным. Платный ключ для тестов всё ещё не выбран.
