# AGENTS.md

Правила для любых ИИ-агентов, которые работают в этом репозитории. Это единственный файл правил: `CLAUDE.md` только подключает его через `@AGENTS.md`. Объём — не больше ~200 строк.

## Состояние проекта

Adviser — расширение VS Code, ИИ-наставник для тех, кто учится программировать. Он разбирает изменённые функции и выдаёт замечание по ступеням: намёк → объяснение → код. Open source (MIT), делается для портфолио.

Версия 0.7.0 вышла 2026-10-23 предварительным выпуском на GitHub Releases (этап 9: доработки по итогам обзора похожих проектов). Идёт этап 10, ветка `stage-10`: подготовка к пилоту — живые проверки Copilot и Jupyter, исправления по ним, eval на настоящих решениях студентов. Есть мастер первого запуска («Adviser: Начало работы») и команда «Adviser: Разобрать эту функцию». Её результат — подчёркивания с намёком и hover с кнопками «Проверь меня», «Объяснить» и «Показать решение»; у объяснения есть пример. В режиме «Наставник» (по умолчанию) автопилот сам разбирает изменённые функции (JS/TS, Python, C/C++, Java, ячейки Jupyter), режим и «Не беспокоить» переключаются в статус-баре. Журнал ошибок помнит каждый случай: на третий раз за неделю hover напоминает «ты так уже делал». В боковой панели «Журнал» видны неделя, частые ошибки и освоенное; есть недельный отчёт, экспорт и очистка. Ещё команды: «Упражнение на частую ошибку» и «Понимаю ли я изменения» (вопросы по коду ИИ-агента). Настройки: `adviser.mode` (`mentor`, `reviewer` — сам, реже и сразу с решением, или `manual`), `adviser.level`, `adviser.language` (язык советов), `adviser.solutionDelay` (пауза перед решением); в `.adviser/config.json` — ещё и правила курса (`course`). Провайдеры: `openai-compatible`, `copilot` (модели GitHub Copilot через `vscode.lm`, без ключа), `claude-code` (только для разработки) и mock. Интерфейс — на английском и русском. Советы оцениваются через `npm run eval` (наборы `cases`, `socratic`, `students`, `check`, `exercise`, `changes`), базовая линия — в `docs/evals/`. Черновики агента, которые автор ещё не вычитал: промпты в `prompts/` (`mentor.v1`–`v3`, `check.v1`, `exercise.v1`, `changes.v1`, `changes-check.v1`), список `patterns/patterns.json`, наборы `evals/*.json` и промпт судьи `evals/judge.v1.md`. Расширение работает на `mentor.v3` (`PROMPT_VERSION`): автор поручил агенту решать самому, а eval у v3 не хуже v2. План со всеми принятыми решениями лежит в `docs/PLAN.md`. Работа идёт по этапам 0–9 (раздел 10 плана). У каждого этапа есть критерий «Готово, когда» — по нему и проверять готовность.

План — рабочий документ. В разделе 16 собраны открытые вопросы: имя, язык советов по умолчанию, писать ли `patterns.json` вручную и другие. Не решать их молча, а спрашивать. `adviser` — рабочее имя: под ним id команд, ключи настроек и папка `.adviser/`. Если имя сменится, переименование делается одной заменой до первой публикации.

## Команды

- `npm run lint` — ESLint, предупреждения тоже валят проверку;
- `npm run format` / `npm run format:check` — Prettier (Markdown он не трогает);
- `npm run check-types` — tsc. `src/` и юнит-тесты проверяются по правилам бандлера (`module: Preserve`): их собирают esbuild и Vitest, а `ai` и `vitest` выходят только как ESM. Интеграционные тесты tsc компилирует отдельно, в CommonJS (`test/integration/tsconfig.json`), потому что mocha грузит их через `require`;
- `npm run test:unit` — Vitest; один файл: `npx vitest run test/unit/<name>.test.ts`;
- `npm run test:integration` — mocha внутри VS Code (`@vscode/test-cli`), тесты в `test/integration/`. Первый запуск скачивает VS Code в `.vscode-test/`. Тесты идут в русском VS Code (`--locale ru` и русский языковой пакет); на Windows в пути с пробелом пакет ставится руками, команда — в README («Разработка»);
- `npm run compile` — сборка esbuild в `dist/extension.js`; запуск расширения — F5 (Extension Development Host);
- живой прогон в VS Code без участия человека (F5, команды, скриншоты): `node .claude/skills/run-vscode/driver.mjs f5 "cmd …" "ss имя"`, подробности в `.claude/skills/run-vscode/SKILL.md`.

- `npm run eval` — оценка советов на наборе `evals/cases.json` (по умолчанию `claude-code`, Sonnet). Ходит в модель, поэтому в CI не входит. Параметры — `npm run eval -- --help`. Метрики и базовая линия описаны в `docs/evals/README.md`. Если меняется промпт или `patterns.json`, прогнать eval и сравнить с базовой линией.

- `npm run package:vsix` — собрать `adviser-<версия>.vsix` (`@vscode/vsce`).

CI (`.github/workflows/ci.yml`) гоняет линт, формат, типы, оба вида тестов и собирает `.vsix` (артефакт прогона). Тег `vX.Y.Z` запускает `.github/workflows/release.yml`: проверяет, что версия в `package.json` та же, и выпускает `.vsix` на GitHub Releases с разделом из CHANGELOG.md. Тексты для пользователя — README.md, PRIVACY.md, CHANGELOG.md и шаги мастера в `walkthrough/`; в PRIVACY.md писать только то, что делает код.

## Архитектура (разделы 4, 6, 8, 9 плана)

Запрос проходит по цепочке: трекер изменений → планировщик → сборщик контекста → фильтр приватности → кэш → движок (промпт → модель → JSON) → наставник (ступени) → журнал ошибок → обратная связь. Через все этапы проходят два модуля: профиль и правила, а также бюджет и доступ к моделям.

**Главное правило: `src/core/` не импортирует `vscode`** (это проверяет ESLint, `no-restricted-imports`). Планировщик, контекст, промпт, схема, ступени, журнал, профиль, кэш, бюджет и маскировка написаны как чистая логика и покрываются юнит-тестами. С редактором работают только тонкие адаптеры в `src/editor/`. Провайдеры моделей лежат в `src/providers/` за общим интерфейсом.

Решения, которые затрагивают сразу несколько модулей:

- **Границы функций берём из языкового сервера** (`vscode.executeDocumentSymbolProvider`). Если символов нет, берём изменённые строки ±10. Свои парсеры и tree-sitter не писать, пока языковые серверы справляются.
- **Модели подключаем через Vercel AI SDK (`ai`).** В MVP — OpenAI-совместимый провайдер (OpenRouter, Ollama через `/v1`, LM Studio и др.) и mock. Anthropic появится в v0.5. Тесты ходят только в mock, чтобы не тратить токены.
- **Провайдер `claude-code` — только для разработки.** Это подписка Claude автора через незамодифицированный `claude -p`. Правила Anthropic не разрешают продуктам ходить через подписки пользователей, поэтому в установленном расширении (`ExtensionMode.Production`) он, как и mock, не включается. Пользователям его не предлагать и в мастер не добавлять.
- **Автопилот разбирает только функции, которые человек правил** (`src/editor/autopilot.ts`, логика — в `src/core/changes.ts` и `src/core/scheduler.ts`). Поводы для разбора: сохранение вручную (не автосохранение), уход курсора из функции, пауза 30 с. Правки только в пробелах и комментариях и перечитывание файла с диска не считаются. Функции с Error-диагностиками, недавно разобранные (cooldown) и сверх лимитов в час и в сутки ждут. Разборы идут по одному. Если функцию правят, пока её разбирают, разбор отменяется. Кэш (`src/core/cache.ts`) — по провайдеру, полному тексту промпта и коду.
- **Журнал ошибок** (`src/core/journal.ts`, хранение — `src/editor/journal.ts`). Случай — это замечание. Если та же функция разобрана снова и тот же `patternId` нашёлся опять, это тот же случай: открытая ступень сохраняется. Пропавшее замечание считается исправленным, а «дошёл сам» — исправлено без третьей ступени. Журнал — JSON в `globalStorageUri`; перед записью он сливается по id с файлом, потому что файл пишут и другие окна. Чтобы случаи не путались, замечания едут вместе с текстом (`trackRange`). Пять частых ошибок за три недели идут в промпт через `{{profile}}`, если это место в промпте есть. Правка строк замечания прячет его до нового разбора. В лампочке у замечания — «понял», «не согласен», «больше не показывать» (`src/editor/feedback.ts`). Ответ пишется в журнал, и новый разбор того же случая его не возвращает. Скрытые типы ошибок лежат в `adviser.hiddenPatterns`; после трёх «не согласен» по одному типу Adviser сам предлагает его скрыть.
- **Окружение функции** (`src/core/contextBuilder.ts`) состоит из трёх частей: что уже нашли линтер и компилятор в этих строках, остальной файл без тел функций и версии зависимостей. Части идут по важности и обрезаются по бюджету. Блок `<context>` уходит модели, только если промпт сам упоминает этот тег: иначе модель приняла бы окружение за код на разбор. Первые строки констант в скелет не берём: в значении бывает ключ. Черновик промпта можно погонять в F5 настройкой `adviser.dev.prompt` (только из исходников). Правила стиля проекта (`.adviser/rules.md`, а с `readAgentFiles` ещё и AGENTS.md, CLAUDE.md, `.cursorrules`, `.github/copilot-instructions.md`) идут в системную часть через `{{rules}}`. Это данные в тегах `<rules>`: шаблон их не разворачивает, а теги внутри текста вырезаются (`src/core/rules.ts`).
- **Ответ модели — строгий JSON по zod-схеме** (`src/core/reviewSchema.ts`, пример в 6.4). На невалидный ответ — один повтор, потом тихая ошибка. Нет сети или пришёл 429 — никаких всплывающих окон: значок в статус-баре и повтор с паузой. Отказ, который повтором не лечится (нет доступа к моделям Copilot, исчерпан лимит тарифа), провайдер бросает как `ProviderRefusal` с причиной для человека: разбор получает `refused`, причина — в статус-баре.
- **Все три ступени приходят одним запросом** (`hint`, `explanation`, `fix`), а расширение открывает их по кликам (`src/core/disclosure.ts`). Намёк пропускается только у уязвимостей (категория `security`) и когда его убрал фильтр утечек (`src/core/hintGuard.ts`). Раньше пропускался у всех `critical`, но на настоящих ошибках новичков модель ставит `critical` 77% замечаний, и учащийся почти не видел намёков. В режиме «Ревьюер» ступеней нет.
- **«Замечаний нет» — нормальный ответ.** На функцию не больше 3 советов, есть порог уверенности. Замечания линтера и компилятора идут в контекст, чтобы модель их не повторяла.
- **`patternId` берётся из `patterns/patterns.json`**, а если ничего не подошло — `other`. Id не из списка расширение само заменяет на `other` и пишет в лог. На этих id держится журнал повторов: после вычитки автором их не переименовывать и не удалять, только добавлять новые.
- **Номера строк в ответе считаются от начала функции.** В строки файла их пересчитывает расширение.
- **Серьёзность превращается в уровень диагностики VS Code:** `critical` → Warning, `warning` → Information, `suggestion` → Hint. Уровень Error не использовать никогда.
- **В промпте сначала идёт всё стабильное** (инструкция, правила, профиль), а код — в конце: так работает кэширование у провайдера. Промпты лежат в `prompts/` с версией в имени (`mentor.v1.md`). Версия входит в ключ кэша, поэтому изменённый промпт сохраняется как новый файл с новой версией.
- **Расход и лимиты** (`src/core/budget.ts`, `src/editor/usage.ts`). Провайдеры сообщают токены через `onUsage`, расход по дням лежит в globalState и виден в подсказке статус-бара. Цены и лимиты в $ задаёт только пользователь (`adviser.budget.*`, scope `machine`); своих цен в коде нет. Лимит исчерпан — разборы на паузе, кроме ответов из кэша, а если задана `adviser.budget.fallbackModel` — идут через запасную модель. Запасная модель — только на `localhost`, и её расход в бюджет не идёт.
- **Хранение:** ключи только в SecretStorage, журнал — JSON-файлы в `globalStorageUri`. Никаких нативных модулей (sqlite и т. п.), иначе расширение придётся собирать под каждую ОС.
- **Настройки в три слоя:** настройки VS Code → `.adviser/config.json` → `.adviser/rules.md`. Проектные перекрывают пользовательские, **кроме провайдера, адреса сервера и модели — их берём только из настроек пользователя.** Иначе чужой репозиторий сможет отправить код и ключ на свой сервер. Лимиты и режим проект может только ужесточить: поднять лимиты или включить автопилот тому, кто выбрал «Вручную», он не может. Если `.adviser/config.json` не разобрался, разборы в его папке стоят: опечатка не должна молча выключить `ignore`. Схема — `src/core/projectConfig.ts` (описания английские); `schemas/adviser-config.schema.json` и русскую `.ru.json` (перевод описаний — `l10n/config-schema.ru.json`) генерирует из неё тест (`npx vitest -u`), VS Code берёт схему на языке интерфейса через `package.nls*.json`. Адрес Ollama всегда задаётся в настройках: в WSL и по SSH `localhost` указывает на другую машину.
- **Безопасность:** в недоверенных папках (Workspace Trust) расширение выключено. Код и правила из репозитория попадают в промпт только как данные. Советы применяются только по клику и с превью. Файлы `.env*` и всё из `.adviserignore` не отправляются, секреты маскируются до отправки (`src/core/redact.ts`: форматы ключей, присваивания «секретным» переменным, строки с высокой энтропией; число строк не меняется). Телеметрии нет.
- **Строки интерфейса — через `vscode.l10n.t`, исходная строка английская.** Русский перевод — в `l10n/bundle.l10n.ru.json`, тексты `package.json` — в `package.nls.json` и `package.nls.ru.json`. Ключ — литерал, места для значений `{0}`; формы числа — одной строкой (`time|times` → `раз|раза|раз`, `pluralForm`). Ядро получает перевод параметром (`Translate` из `src/core/i18n.ts`), в расширении это `translate` из `src/editor/bundled.ts`. `test/unit/l10n.test.ts` проверяет, что перевод есть у каждой строки. Лог пишется по-английски и не переводится, тексты для модели (промпт, окружение) — тоже.
- **Запросы к модели, кроме разбора, — через `Reviewer.ask`:** провайдер, бюджет, согласие (если уходит код), маскировка секретов, повтор на ответ не по схеме (`runStructured`).
- **Webview-панель делаем на `@vscode-elements/elements`.** Официальный Webview UI Toolkit закрыт с 1 января 2025, его не использовать.
- **`engines.vscode` — `^1.101.0`, а не последняя версия:** Cursor и Windsurf отстают от VS Code. `@types/vscode` держать на той же версии (`~1.101.0`), чтобы случайно не взять API, которого там ещё нет.

## Правила работы (раздел 11 плана)

- К каждой функции ядра — тест в `test/unit/`.
- Новые зависимости — только по согласованию.
- Тексты промптов и объяснений автор пишет или вычитывает сам. Правки в `prompts/` и в формулировках объяснений предлагать, а не вносить молча.
- Задачи ставятся по шаблону: цель, файлы, «Готово, когда», «Не трогать» (пример в разделе 11). Список «Не трогать» соблюдать.
- Eval-набор (этап 3) делается раньше автоматики (этап 4), менять их местами нельзя.
- Коммит после каждой рабочей задачи, отдельная ветка на каждый этап (`stage-0`, `stage-1`, …).

## Публикация (раздел 13 плана)

Пошагово — в `docs/RELEASE.md`.

- Marketplace: `vsce publish --oidc` из GitHub Actions (trusted publishing). Personal access token не заводить: Azure DevOps отключает глобальные PAT 1 декабря 2026.
- Open VSX: через `ovsx`, токен хранится в секретах CI.
- Версии: нечётная минорная цифра — pre-release (0.3.x, 0.5.x), чётная — релиз (1.0.x).
