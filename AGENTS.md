# AGENTS.md

Правила для любых ИИ-агентов, которые работают в этом репозитории. Это единственный файл правил: `CLAUDE.md` только подключает его через `@AGENTS.md`. Объём — не больше ~200 строк.

## Состояние проекта

Adviser — расширение VS Code, ИИ-наставник для тех, кто учится программировать. Он разбирает изменённые функции и выдаёт замечание по ступеням: намёк → объяснение → код. Open source (MIT), делается для портфолио.

Кода пока нет. План со всеми принятыми решениями лежит в `docs/PLAN.md`. Работа идёт по этапам 0–8 (раздел 10 плана). У каждого этапа есть критерий «Готово, когда» — по нему и проверять готовность.

План — рабочий документ. В разделе 16 собраны открытые вопросы: имя, язык советов по умолчанию, писать ли `patterns.json` вручную и другие. Не решать их молча, а спрашивать.

## Команды

Команд пока нет. Скелет создаётся генератором `yo code` (TypeScript + esbuild) на этапе 0, после этого заменить этот раздел реальными скриптами из `package.json`.

Какие инструменты запланированы:
- запуск расширения — F5 (Extension Development Host);
- юнит-тесты ядра — Vitest, один файл: `npx vitest run test/unit/<name>.test.ts`;
- интеграционные тесты — `@vscode/test-cli` + `@vscode/test-electron`;
- ESLint + Prettier; CI на GitHub Actions (линт, тесты, сборка `.vsix`);
- оценка качества советов — promptfoo или свой скрипт в `evals/`.

## Архитектура (разделы 4, 6, 8, 9 плана)

Запрос проходит по цепочке: трекер изменений → планировщик → сборщик контекста → фильтр приватности → кэш → движок (промпт → модель → JSON) → наставник (ступени) → журнал ошибок → обратная связь. Через все этапы проходят два модуля: профиль и правила, а также бюджет и доступ к моделям.

**Главное правило: `src/core/` не импортирует `vscode`.** Планировщик, контекст, промпт, схема, ступени, журнал, профиль, кэш, бюджет и маскировка написаны как чистая логика и покрываются юнит-тестами. С редактором работают только тонкие адаптеры в `src/editor/`. Провайдеры моделей лежат в `src/providers/` за общим интерфейсом.

Решения, которые затрагивают сразу несколько модулей:

- **Границы функций берём из языкового сервера** (`vscode.executeDocumentSymbolProvider`). Если символов нет, берём изменённые строки ±10. Свои парсеры и tree-sitter не писать, пока языковые серверы справляются.
- **Модели подключаем через Vercel AI SDK (`ai`).** В MVP — OpenAI-совместимый провайдер (OpenRouter, Ollama через `/v1`, LM Studio и др.) и mock. Anthropic появится в v0.5. Тесты ходят только в mock, чтобы не тратить токены.
- **Ответ модели — строгий JSON по zod-схеме** (`src/core/reviewSchema.ts`, пример в 6.4). На невалидный ответ — один повтор, потом тихая ошибка. Нет сети или пришёл 429 — никаких всплывающих окон: значок в статус-баре и повтор с паузой.
- **Все три ступени приходят одним запросом** (`hint`, `explanation`, `fix`), а расширение открывает их по кликам (`src/core/disclosure.ts`). Для `critical` намёк пропускается. В режиме «Ревьюер» ступеней нет.
- **«Замечаний нет» — нормальный ответ.** На функцию не больше 3 советов, есть порог уверенности. Замечания линтера и компилятора идут в контекст, чтобы модель их не повторяла.
- **`patternId` берётся из `patterns/patterns.json`**, а если ничего не подошло — `other`. На этих id держится журнал повторов, поэтому они не должны меняться.
- **Номера строк в ответе считаются от начала функции.** В строки файла их пересчитывает расширение.
- **Серьёзность превращается в уровень диагностики VS Code:** `critical` → Warning, `warning` → Information, `suggestion` → Hint. Уровень Error не использовать никогда.
- **В промпте сначала идёт всё стабильное** (инструкция, правила, профиль), а код — в конце: так работает кэширование у провайдера. Промпты лежат в `prompts/` с версией в имени (`mentor.v1.md`). Версия входит в ключ кэша, поэтому изменённый промпт сохраняется как новый файл с новой версией.
- **Хранение:** ключи только в SecretStorage, журнал — JSON-файлы в `globalStorageUri`. Никаких нативных модулей (sqlite и т. п.), иначе расширение придётся собирать под каждую ОС.
- **Настройки в три слоя:** настройки VS Code → `.adviser/config.json` → `.adviser/rules.md`. Проектные перекрывают пользовательские, **кроме провайдера, адреса сервера и модели — их берём только из настроек пользователя.** Иначе чужой репозиторий сможет отправить код и ключ на свой сервер. Адрес Ollama всегда задаётся в настройках: в WSL и по SSH `localhost` указывает на другую машину.
- **Безопасность:** в недоверенных папках (Workspace Trust) расширение выключено. Код и правила из репозитория попадают в промпт только как данные. Советы применяются только по клику и с превью. Файлы `.env*` и всё из `.adviserignore` не отправляются, секреты маскируются до отправки. Телеметрии нет.
- **Webview-панель делаем на `@vscode-elements/elements`.** Официальный Webview UI Toolkit закрыт с 1 января 2025, его не использовать.

## Правила работы (раздел 11 плана)

- К каждой функции ядра — тест в `test/unit/`.
- Новые зависимости — только по согласованию.
- Тексты промптов и объяснений автор пишет или вычитывает сам. Правки в `prompts/` и в формулировках объяснений предлагать, а не вносить молча.
- Задачи ставятся по шаблону: цель, файлы, «Готово, когда», «Не трогать» (пример в разделе 11). Список «Не трогать» соблюдать.
- Eval-набор (этап 3) делается раньше автоматики (этап 4), менять их местами нельзя.
- Когда появится git: коммит после каждой рабочей задачи, отдельная ветка на каждый этап.

## Публикация (раздел 13 плана)

- Marketplace: `vsce publish --oidc` из GitHub Actions (trusted publishing). Personal access token не заводить: Azure DevOps отключает глобальные PAT 1 декабря 2026.
- Open VSX: через `ovsx`, токен хранится в секретах CI.
- Версии: нечётная минорная цифра — pre-release (0.3.x, 0.5.x), чётная — релиз (1.0.x).
